# 환경·의사결정 v3 — 사용 안내와 변경 범위

2026-11-24 첨부 `metrorookies_vworld_roadview(2).zip`을 기준으로 수정했다. V-World·카카오 로드뷰와 기존 차량·인물·물류 애니메이션을 유지하면서 실제 공간정보와 원본 배차계획을 연결했다.

## 가장 먼저 실행하기

1. 전체 ZIP을 **새 폴더**에 풀고 `index.html`, `app.js`, `serve.py`, `data`, `assets`, `vendor`가 함께 있는지 확인한다.
2. 이 폴더의 탐색기 주소창에 `cmd`를 입력한다.
3. 명령 프롬프트에서 `py serve.py`를 실행한다. Python 명령을 사용하던 환경이면 `python serve.py`를 쓴다.
4. 자동으로 열리는 `http://localhost:8081/`에 접속한다. 서버 창은 열어 둔다.
5. 화면의 **환경·의사결정 v3** 표시와 **DRT 경로 및 의사결정** 버튼을 확인한다.
6. 기존 V-World 키를 입력하고 연결한다. 데이터는 ZIP 안에 있으며 지도 공급원 연결 후 주변 구역부터 자동 표시한다.

원래 8080을 사용하려면 `py serve.py --port 8080`으로 실행한다. V-World와 카카오 개발자 설정의 등록 주소는 실제 사용하는 호스트·포트와 일치해야 한다. `serve.py`는 실행 위치와 관계없이 자기 파일이 있는 프로젝트 폴더를 제공하므로 다른 폴더를 서빙해 404가 나는 문제를 줄인다. 별도 설치 파일은 없다.

기존 방식도 사용할 수 있다.

```sh
py -m http.server 8081 --bind 127.0.0.1
```

이 명령은 반드시 `index.html`이 있는 폴더에서 실행해야 한다. HTML 더블클릭 방식은 지원하지 않는다. 예전 화면이 나오면 기존 서버를 `Ctrl+C`로 종료하고 새 폴더에서 서버를 연 뒤 `Ctrl+F5`를 누른다. `index.html`과 `gangnae_vworld_qgis_3d_fixed.html`은 같은 최신 진입 화면이다.

## 새 모드 사용하기

카메라 버튼 옆 **DRT 경로 및 의사결정**을 누르면 지도 영역이 50:50으로 나뉜다.

| 왼쪽 | 오른쪽 |
|---|---|
| 기존 V-World와 선택 차량 주행 | 현재까지 수신된 여객 호출 |
| 실제 건물·도로 면·교량 | 배정 차량·약속 승차 대기·점수 평가 후보 수 |
| 차량·사람·상자 애니메이션 | 직전 기록 계획과 갱신 계획의 다음 작업 |
| 이전 계획·갱신 계획의 도로 선형 | 도로망을 이용한 두 계획의 경로 비교 |
| 선택 차량 추적 | 기존 승객의 예정 대기 변화·물류 다음 방문 ETA 변화 |

두 화면은 같은 날짜·운영 방식·S0/S1/S2·차량·시간을 사용한다. 되감기는 과거 시점의 기록과 계획을 다시 계산해 복원한다. 오른쪽에는 별도의 차량 추적 영상을 중복해서 배치하지 않았다. 다른 카메라 버튼을 누르면 원래 전체 지도 화면으로 돌아간다.

오른쪽의 ‘이전/다음’은 저장된 계획 시점으로 이동하는 재생 탐색이다. 미래의 호출을 미리 받은 것처럼 표시하지 않는다. 노선 그림은 긴 계획의 앞 12개 작업까지 표시하며 잘린 경우 범례에 표시한다. 작업 목록은 앞 6개와 남은 개수를 표시한다.

### 실제 로그에서 확인할 수 있는 재배차 사례

| 설정 | 값 |
|---|---|
| 날짜 | 2023-11-06 |
| 운영 방식 | 여객 + 물류 |
| 시나리오 | S1 |
| 시각 | 08:32:31 (`time_min=152.5166667`) |
| 비교 차량 | DRT 1 또는 2 |
| 새 호출 | 1016631 |
| 점수까지 평가한 삽입 후보 | 75개 |
| 기록된 약속 대기시간 | 약 2.92분 |

이 시점에 탑연5리 경로당 `HUB_33`의 다음 계획 하차 차량은 1에서 2로 바뀐다. 다음 방문 ETA는 08:44:10에서 09:03:37로 바뀌어 약 19.44분 차이가 난다. 이는 두 기록 계획의 차이이며 특정 택배 하나의 최종 배송 지연이나 물류만의 인과효과를 뜻하지 않는다.

원본에는 다른 미선택 후보별 상세 점수·기각 이유가 없다. 따라서 그런 표나 차량의 ‘고민’을 임의로 만들지 않았다. 선택한 계획의 변화와 검증한 ETA를 비교한다. 현재 재생기는 브라우저에서 새 배차 알고리즘을 실행해 원본 실적을 바꾸는 방식이 아니다.

## 공간정보 표시 범위

지도 위 **실제 공간정보**를 열면 건물·도로 면·교량·표고점 보정을 개별적으로 켜고 끌 수 있다. 강내면 경계는 기존과 같이 기본 포함된 테두리 레이어다.

| 항목 | 포함 자료 | 표시 원칙 |
|---|---:|---|
| 건물 | 외곽선 8,666개 | 외곽선 그대로 입체화; 높이·층수 및 용도에 따라 표현 |
| 도로 | 면 5,174개 | 실제 도로경계 내부에 포장·비포장·미확인 표면 표시 |
| 표고점 | 2,761개 | 보간된 국소 높낮이를 기존 지형에 완만하게 반영 |
| 교량 | 외곽선 92개 | 외곽선 유지, 접근부 지형으로 상판 고도 추정 |

건물 1,752개는 정상 범위의 제공 높이를 사용하고, 1,242개는 층수로 높이를 추정한다. 나머지 5,672개는 높이 미확인 대체 표현이다. 다른 지역 주소가 들어 있는 42개 도형은 그 속성값으로 높이나 용도를 단정하지 않았다. 외벽·평지붕의 색상은 용도별 시각화이며 실제 외관 사진을 복원한 것이 아니다.

기존 지도 지형을 그대로 공급받고, 지원되는 엔진에서 표고 보간과 원 지형을 국소적으로 맞춘 뒤 표본 보정량을 ±1.2m로 제한한다. 기존 0.9 높이 배율 지원 처리는 유지했다. 교량 주변·수면·자료 부족 구간은 보정을 억제하며 공개 API가 맞지 않는 SDK는 원 지형으로 유지한다. 지도 공급원이 지연되면 높이를 모르는 객체는 순차적으로 재시도한다.

교량 상판의 실제 고도·교각 구조는 파일에 없으므로 추정이다. 차량과 카메라는 현재 표시된 교량 표면에 맞추되, 수평 경로와 시각·수량은 바꾸지 않는다. 교량 아래 횡단 도로를 무조건 올리지 않도록 방향 검사를 사용하지만, 도로의 실제 입체 교차 높이 자료를 대신하는 검증은 아니다.

건물 자료의 기준일은 2026-11-06이며 운행 자료는 2023년이다. 이 화면은 2023년의 모든 건물 외관까지 복원한 역사적 실측 모델이 아니다.

## 연구 해석과 유지한 조건

물류는 수요·목적지가 사전에 정해져 있어도 경로는 고정되지 않는다. 원본은 온라인 여객 승하차 삽입과 물류 작업의 순서·적재 방문·차량 배정을 개선하는 휴리스틱을 사용한다. [알고리즘과 원본 로그 설명](dispatch-methodology.md)에 정확한 연산과 목적함수를 정리했다.

- 강내우체국 Depot, DRT 3대, 차량당 여객 11명·물류 8개.
- 7일 × 2가지 운영 방식 × S0/S1/S2의 기존 42개 실행.
- 06:00 기준 경과 분, 06:30 운행 시작, 08:30 물류, 22:00 서비스 종료, 22:30 복귀 기한.
- 가상 주차 탐색은 위치를 고정하고 원본의 시간·거리만 유지.
- 15분을 넘는 대기시간도 원본 그대로 표시.
- S2 비용계수와 별도 운영원가 추정은 구분.
- 위치는 방향성 도로망을 이용한 복원·시간 보간이며 GPS 실측이 아님.
- 차량·사람·문·택배 상자 애니메이션과 정차 간격은 표시용 연출.

## 검증 범위

- 원본 42개 실행 JSON·원본 공간자료·재생 코어와 모델의 SHA-256을 첨부 ZIP과 비교한다.
- 3,186건의 재계산 승차 ETA와 원본 약속 승차시각은 최대 오차 0분이다.
- 7,665개 전체 계획 점수의 거리/대기 성분을 확인했다. S2 미확정 비용계수는 검증·확정했다고 표현하지 않는다.
- 24,344개 방향성 계획 경로의 연결·방향·통행시간 합을 검사했다.
- 전체 8,666개 건물 Polygon, 5,195개 도로 Polygon 부분, 94개 교량 Polygon 부분을 번들 Cesium의 CPU 지오메트리 생성기로 검사했다.
- 기존 42개 실행 재생의 203,230개 검사, 로드뷰 비동기 동작, 경계·시설·상자 애니메이션, 새 패널의 미래 데이터 차단과 되감기 검사를 수행했다.
- 환경 지형 변경과 원래 DEM 공급원의 오류 복구가 충돌하지 않는지, 이전 높이 요청이 새 결과를 덮지 않는지 검사했다.

실제 브라우저는 이 작업 환경의 소켓 제한으로 시작하지 못했다. 따라서 **실제 V-World/Kakao 인증키 응답, GPU 렌더링 결과와 픽셀 배치까지 검증한 것은 아니다.** 제공 범위·인증키 등록 도메인·SDK 버전에 따른 외부 연결은 사용 환경에서 확인해야 한다. 실패하면 기존 지도·원 지형 또는 자료 없음 상태를 사용하도록 처리했다.

자세한 결과는 `release-v3-validation.json`, `dispatch-validation.json`, `dispatch-core-test-results.json`, `review-regression-results.json`과 각 테스트 파일에 있다.

## 코드와 재생성

| 파일 | 역할 |
|---|---|
| `research-workspace.js` | 기존 앱·공간정보·배차 패널의 연결과 실행 변경 관리 |
| `environment3d.js` / `environment-core.js` | 건물·도로·교량과 고도 보정 |

| `dispatch-core.js` | 원본 계획 시점 조회, 이전/새 계획·ETA 변화 |
| `dispatch-panel.js` / `dispatch-panel.css` | 우측 의사결정 화면 |
| `decision-overlay.js` | V-World 위 변경 전후 경로 표시 |
| `data/environment/` | 변환 완료된 92개 공간 타일 및 표고 보간 |
| `data/decisions/` | 42개 조합의 원본 계획·배차 기록 변환 데이터 |
| `scripts/build_environment.py` | 첨부 GeoJSON의 재변환 |
| `scripts/decision_convert.py` | 원본 실행 ZIP의 계획 로그 재변환 |
| `serve.py` | 프로젝트 위치를 자동으로 잡는 로컬 서버 |

일반 실행에는 데이터 변환이 필요 없다. 모든 파생 파일이 ZIP에 포함된다. 재생성할 때 필요한 자료와 명령은 [공간정보 설명](environment-data.md), [배차 데이터 설명](dispatch-methodology.md)에 있다.

팀원에게는 전체 ZIP을 전달하면 된다. localhost 링크만 보내면 다른 사람의 컴퓨터에서 이 서버로 연결되지 않는다. GitHub Pages 등 공개/공유 호스팅과 API 도메인 등록은 이 ZIP 수정 작업과 별도이며 이번 작업에서는 배포하지 않았다.
