# V4 원본 자료 재검증

확인일: 2026-11-25. GitHub 연결 도구로 [km-minsang/MetroRookies](https://github.com/km-minsang/MetroRookies)의 `main` 참조와 전체 Git tree를 다시 읽었다. 현재 커밋은 `62f78246e3f0547607d0b95d944a9da981699fc1`이며 V3 변환에 사용한 커밋과 같다.

## 파일의 일치 여부

`김민상_강내면_온라인DRT_주차3분_코드.zip`과 2023-11-06~12 결과 ZIP 7개의 실제 바이트로 Git blob SHA를 계산하여 현재 GitHub tree의 SHA와 비교했다. **8개 모두 일치했다.** 코드 ZIP의 blob SHA는 `e90577bfd686b4eab839e72d5e799b8856fc095e`이다.

도로망·속도·호출·물류 입력 4종의 GitHub blob도 기존 `data/manifest.json`의 원본 계보와 일치한다. 이어 42개 조합 각각의 ZIP 내부 `plans.jsonl`과 `decisions.csv` SHA256을 `data/decisions`의 출처 해시와 대조했다. 모두 일치하며, 각 의사결정 파일에 명시된 재생 데이터 해시도 해당 `data/runs` 파일과 일치한다. 재생용 원본 로그, 경로, 시각, 탑승량과 적재량은 이번 시각 개선에서 다시 계산하거나 바꾸지 않았다.

상세 파일 경로·8개 SHA·42개 확인 결과는 `source-verification-v4.json`에 있다. 검증 재현 프로그램은 `scripts/verify_source_v4.py`다. 외부 원본 ZIP과 GitHub에서 받은 tree JSON을 인자로 지정하며 다운로드나 최적화를 수행하지 않는다.

## 의사결정 화면에서 사용하는 의미

| 화면 정보 | 확인한 근거 | 해석 |
| --- | --- | --- |
| 현재 DRT 위치·방향 | `replay-core.js`의 `stateAt` / `sampleRoute`, 원본 `routing.py` | 기록된 구간의 도로망·통행시간에 따른 위치 보간. GPS 측정 위치 아님 |
| 새 여객 호출·배정 차량 | `engine.py`의 `run_online`, `optimizer.py`의 `accept_passenger` | 호출 시각이 된 요청만 공개·배정 |
| 검토 후보 수 | `optimizer.py`의 `_insertions` 반복 이후 `tested` 증가 | 제약을 통과한 삽입 후보 수. 실패한 모든 검사 횟수와 다름 |
| 약속 대기 | 원본 `promised_pickup_min - time_min` | 배정 당시 약속한 승차 대기 |
| 기존·변경 계획 | `engine.py`의 `snapshot`, `plans.jsonl` | 직전 기록 계획과 현재 기록 계획. 동일 호출에서 거절된 대안 목록 아님 |
| 계획 대기·물류 ETA 변화 | 검증된 도로 통행시간으로 두 기록 계획을 재계산 | 계획 간 차이. 특정 물류 작업만의 인과적 지연이라고 해석하지 않음 |
| 가상 주차 탐색 | 원본 설정 및 `replay-core.js`의 `PARK_SEARCH` 처리 | 시간·거리 회계만 반영하며 지도상 마지막 서비스 노드에 머묾 |

`optimizer.py`에서 S0는 거리→대기, S1은 대기→거리, S2는 비용 가중합→거리 순으로 평가한다. 대기는 인원 가중합이며 점수는 전체 차량의 남은 계획 기준이다. `RELOCATE_STOP`, `RELOCATE_TRIP`, `TRANSFER_UNLOADED_UNIT`을 통해 물류 작업의 순서·차량도 변경하므로 **물류 수요가 사전 확정되어도 배송 경로가 고정인 것은 아니다.** `config/default.json`의 대기 한도는 `1e9`분으로 사실상 해제되어 있고 15분 제한을 새로 적용하지 않았다.

기존 ETA 검증 결과는 3,186개 승차 약속과 차이 0분, 7,665회 전체 차량 점수 비교에서 부동소수점 오차 이내다(`dispatch-validation.json`). V4의 파일 일치 검사는 이 검증에 사용된 원본이 현재 GitHub 자료와 같음을 재확인한다. 검증 수치를 시각 개선의 새 최적화 결과로 주장하지 않는다.

## 핵심 시설과 일반 건물

실제 공간 도형을 겹쳐 검사한 결과, 우체국 전용 모형과 일반 건물 ID `196849`가 겹친다. 이 일반 건물 높이는 7.3m이고 전용 우체국 모형 높이는 약 3.83m다. 따라서 일반 건물 면이 우체국 모형을 가릴 수 있는 구조적 원인이 확인된다. 사용자 PC의 실제 WebGL 화면을 측정한 결과는 아니다.

`facility-priority.js`는 기존 전용 모형의 내보낸 외곽 치수와 동일한 위치·방향을 사용한다. 모형 가장자리에 0.15m만 더한 사각형과 실제 겹치는 일반 건물 성분을 그리지 않는다. 전체 8,666개 중 37개가 해당한다(우체국 1, 물류하차지 30, 정류장 6). 주변 건물을 거리 반경으로 일괄 제거하지 않으며, 건물 안마당의 빈 공간에 들어가는 모형은 충돌로 계산하지 않는다. 여러 성분이 있는 MultiPolygon은 충돌한 성분만 제외한다.

이것은 표시 우선순위이며 원본 건물 파일을 삭제하거나 시설의 조사된 외곽선이라고 바꾸지 않는다. 기존 시설 배치 좌표, 정류장 대기 위치, 사람 이동, 차량 서비스 시각, GLB 파일은 유지된다. 전용 시설의 최소 픽셀 크기는 0, 배율은 1이라 줌을 멀리한다고 건물 크기를 과장하지 않는다. 표시 거리만 우체국 12km·물류하차지 1.8km·정류장 900m로 늘렸다. 더 멀리서는 실제 크기대로 작아진다.

시설 및 일반 건물의 창문·문·지붕은 알아보기 위한 외형 표현이다. 실제 GIS 외곽선·높이/층수·용도가 있는 범위는 활용하지만, 자료에 없는 실제 외벽 사진이나 지붕 재료까지 촬영한 것처럼 표시하지 않는다. 개별 일반 건물의 이름 라벨은 추가하지 않는다.

시설 충돌 목록은 `facility-priority-audit-v4.json`에, 형상·회전·안마당·부분 겹침·실제 우체국 회귀 검사는 `tests/facility-priority.test.mjs`에 있다.

회전 검사는 이름이나 사각형 크기만 비교하지 않는다. 배포한 GLB 4종의 실제 정점과 node 변환을 읽고, Cesium의 Y-up/Z-forward 축 보정, `scene3d.js`와 같은 `heading+90°` 지구고정 변환, 역 ENU 변환을 합성했다. 방위 0·90·180·270도와 실제 우체국 배치 방향 227.94675도에서 모형 외곽과 우선 표시 영역의 기본 치수가 모두 0.00001m 이내로 일치했다. 이는 CPU 좌표·기하 검증이며 GPU/브라우저 렌더링을 직접 관찰한 검증과 구분된다.
