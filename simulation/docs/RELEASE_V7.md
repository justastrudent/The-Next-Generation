# MetroRookies 발표 화면 v7

버전 날짜: 2026-11-25

사용자가 제공한 **MetroRookies_Visual_Decision_v6(1).zip**을 기준으로 수정한 전체 실행 패키지입니다. 기존 V-World, 카카오 로드뷰, 청주콜 DRT 모델과 연구 데이터를 유지하면서 요청한 발표 화면·재생 조작·승하차 피드백·정차 우체국 차량을 추가했습니다.

## 실행

1. ZIP 전체를 새 폴더에 압축 해제합니다.
2. 기존 로컬 서버를 실행 중이면 해당 명령창에서 `Ctrl+C`로 종료합니다.
3. `index.html`이 있는 폴더에서 명령창을 열고 `py serve.py --port 8080`을 실행합니다. Python 실행 명령이 `python`인 환경에서는 `python serve.py --port 8080`을 사용합니다.
4. `http://localhost:8080/`을 엽니다. 서버 창은 열어 둡니다.
5. 화면의 **발표 화면 v7** 표시를 확인합니다. 이전 화면이 남으면 `Ctrl+Shift+R`로 새로고침합니다.

`serve.py`의 기존 기본 포트 8081은 유지했습니다. 기존 V-World·Kakao에 등록한 주소와 포트를 사용하세요. 이 패키지가 외부 배포 주소나 API 설정을 자동으로 변경하지는 않습니다.

## 변경 사항

| 항목 | V7 동작 |
| --- | --- |
| 반응형 화면 | PC의 지도·의사결정 50:50 배치를 유지하고, 좁은 휴대폰과 태블릿에서는 가로·세로 화면 높이에 맞춰 재배치합니다. 모바일 브라우저 주소창과 안전 영역을 반영합니다. |
| 의사결정 발표 화면 | 현재 DRT 위치·경로, 신규 호출, 대기·배송 영향의 핵심 값을 함께 배치합니다. 긴 다음 작업 목록과 판단 근거는 펼쳐 보기로 이동했습니다. 작은 화면에서는 운행 선택 등 부가 설정이 아래에 배치될 수 있습니다. |
| 지도 조작 | 지도에 두 손가락 확대·축소와 `+ / −` 버튼을 연결했습니다. 직접 줌하면 차량 추적의 자동 카메라가 사용자 조작을 덮어쓰지 않도록 수동 시점으로 전환합니다. 기존 카메라 버튼으로 복귀할 수 있습니다. 로드뷰 자체 조작은 기존 SDK 동작을 사용합니다. |
| 재생 배속 | 슬라이더와 숫자 입력으로 0.1~600배를 0.1배 단위로 지정합니다. |
| 시간 이동 | 연속 슬라이더 입력은 프레임당 마지막 값으로 모으고, 탐색 중 불필요한 건물 생성과 로드뷰 요청을 줄입니다. 이동을 마치면 최종 시각에 동기화합니다. |
| 신규 여객 호출 알림 | 재생 중 실제 호출 시각을 통과하면 출발·도착지와 호출 시각을 큰 알림으로 표시합니다. 설정에서 켜고 끄거나 닫을 수 있고, 알림이 재생을 정지시키지 않습니다. 시간을 건너뛸 때 지나간 호출을 연속으로 띄우지 않습니다. |
| 승하차 말풍선 | 승차 장면에 실제 대기시간을 표시합니다. 하차 장면에는 최초 배차 계획의 예상 도착시각 대비 지연·조기 도착·정시 여부를 표시합니다. 설정에서 끌 수 있습니다. |
| 우체국 차량 | 강내우체국 옆에 흰색 차체와 빨강·주황 적재함을 가진 정차 소포 차량 한 대를 추가했습니다. 운행하지 않는 장식 모델이며 DRT 3대의 집계에 포함하지 않습니다. |
| 화면 정리 | 왼쪽 위 강내면 안내 카드를 제거했습니다. 도로망·정류장·물류하차지·경계 및 실제 공간정보 표시 제어는 설정에 모았습니다. |

## 시간과 수치의 의미

- **승차 대기시간:** 원본 승차 시각 − 원본 호출 시각입니다.
- **하차 지연:** 원본 하차 시각 − 해당 호출이 처음 배차된 계획의 예상 하차 시각입니다. 뒤에 변경된 계획을 최초 계획 대신 사용하지 않습니다.
- 계획의 예상 시각은 원본 계획 순서에서 검증된 재계산값인 경우 **재계산**으로 구분합니다. 기준 계획이 없으면 수치를 생성하지 않고 예상 도착시각이 없다고 표시합니다.
- 하차 지연은 최초 약속 대비 차이입니다. 물류가 단독으로 유발한 지연이라는 인과효과를 뜻하지 않습니다.
- 시뮬레이션 현재 시각 전에 아직 발생하지 않은 승하차의 실제 결과를 말풍선에 먼저 공개하지 않습니다.
- 승객 호출·승하차·배송·경로 좌표·주차 탐색·시나리오 목적함수와 연구 결과의 원본 값은 변경하지 않았습니다.
- 정차 우체국 차량은 첨부한 참고 사진의 색과 형태를 반영한 시각화 모델입니다. 실제 현장에 존재하는 차량의 측량 기록이나 추가 운행 기록이 아닙니다.

## 검증 결과와 범위

자동 검사 기록은 `v7-validation.json`, `v7-app-regression-results.json`, `v7-replay-validation.json`에 포함되어 있습니다.

- 실행 가능한 20개 테스트 파일의 **71개 Node 테스트가 모두 통과**했습니다. 앱 연결 검사는 그 안에서 **193개 세부 항목**을 확인했습니다.
- 42개 운영 조합을 대상으로 V6 재생 코드와 비교한 **957,444개 차량 상태**에서 수치 차이가 없었습니다. 이벤트 경계, 앞뒤 이동, 무작위 탐색과 모듈 경계 사례를 포함합니다.
- 원본 데이터 파일 **195개**의 바이트가 유지되었습니다. 원본 데이터·기존 모델·배포 라이브러리·주요 알고리즘과 시각화 모듈을 포함한 **604개 보호 대상 원본 파일**도 바이트 변경이 없었습니다.
- 두 HTML 진입 파일의 일치, 필수 UI 연결, 로컬 파일 경로와 JavaScript 문법을 검사했습니다. 반응형 CSS는 소스의 화면 크기 조건과 높이 배분을 검토했습니다.
- 새 우체국 차량의 크기와 배치를 모델·기하 검사로 확인했고, 모델을 별도로 렌더링해 검토했습니다.
- 같은 환경에서 12,000회 시간 위치 계산을 비교한 최종 측정은 V6 약 402ms, V7 약 47ms였습니다. 이는 **재생 계산만의 CPU 측정**으로, WebGL·건물 렌더링·지도 다운로드·브라우저 배치를 포함한 전체 앱의 속도 향상 보장이 아닙니다.

기존 `tests/replay-core.test.mjs`는 이 ZIP에 들어 있지 않은 외부 원본 CSV 경로를 요구하므로 이번 실행 목록에서 제외했습니다. V7의 `tests/replay-seek-v7.test.mjs`는 패키지의 실제 42개 실행 자료와 파일 안에 보존한 V6 기준 구현을 비교합니다.

이 작업 환경에서는 브라우저 보안 정책 때문에 로컬 페이지를 열 수 없었습니다. 따라서 실제 V-World·Kakao 인증/영상, 모바일 기기의 GPU 성능, 터치 제스처와 최종 화면의 픽셀 배치는 직접 검증하지 못했습니다. 화면 크기에 따른 레이아웃과 조작은 코드에 반영했지만 모든 기기에서 확인했다고 주장하지 않습니다.

## QR로 열기

기존 QR이 가리키는 호스팅에 V7의 전체 파일을 반영해야 휴대폰에서도 새 버전이 보입니다. ZIP 다운로드만으로 기존 배포 사이트가 갱신되지는 않습니다. `localhost`는 각 기기 자신의 주소이므로 PC의 `localhost` 주소를 휴대폰 공유용 QR에 넣지 마세요.

배포 후 실제 휴대폰에서 가로·세로 전환, 지도 두 손가락 줌, 의사결정 핵심 정보의 동시 표시를 확인하세요. API 등록 도메인은 기존 배포 주소와 일치해야 합니다.

## 검증 재실행

Node.js가 있는 환경에서 프로젝트 폴더를 기준으로 다음 명령을 실행할 수 있습니다. Python은 테스트 파일 목록을 넘기는 데만 사용합니다.

```sh
python -c "import pathlib,subprocess; files=sorted(str(p) for p in pathlib.Path('tests').glob('*.mjs') if p.name!='replay-core.test.mjs'); raise SystemExit(subprocess.call(['node','--test',*files]))"
```

일부 기존 테스트는 과거 버전의 보고서 파일을 다시 씁니다. 배포에 필요한 데이터는 바꾸지 않습니다. 이번 V7 검사 결과는 `v7-` 접두어의 별도 보고서로 보존했습니다.
