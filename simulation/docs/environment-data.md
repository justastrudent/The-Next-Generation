# 실제 강내면 공간정보 레이어

이 버전은 ZIP에 첨부된 QGIS GeoJSON을 자동으로 읽을 수 있는 정적 타일로 변환하여 V-World 위에 표시한다. 카카오 로드뷰, 차량 경로, 승하차 시간과 시뮬레이션 원본 결과는 이 레이어가 수정하지 않는다.

## 포함된 자료

| 원본 파일 | 객체 수 | 사용 내용 |
|---|---:|---|
| `data/gangnae_buildings.geojson` | 8,666 | 실제 건물 외곽선, 높이·층수·용도 속성 |
| `data/gangnae_roads001.geojson` | 360 | 부지 안 도로 314개와 도로경계 46개 |
| `data/gangnae_roads002.geojson` | 4,814 | 도로경계 면 |
| `data/gangnae_road_attributes.geojson` | 9,434 | 중심선의 포장·폭·차로 속성 |
| `data/gangnae_elevation.geojson` | 2,761 | NUME 표고점 |
| `data/gangnae_bridges.geojson` | 92 | 교량 외곽선·폭·연장 |

도로 001과 002는 동일한 UFID가 없고 정규화한 외곽선의 완전 중복도 없었다. 두 파일을 함께 사용한다. 도로를 임의의 폭으로 다시 만들지 않고 제공된 면을 그대로 사용한다. 좌표 소수점 일곱째 자리까지 유지하며 Polygon 내부 구멍과 MultiPolygon을 보존한다. 시뮬레이션용 `split_links_4326.geojson`과 렌더링용 도로 면은 서로 다른 역할을 유지한다.

## 건물의 높이와 외관

필드 의미는 한국교통연구원 「2024년 국가교통조사 및 분석 — KTDB 모빌리티 기반지도 구축」 표 5-15에서 확인했다.

- A16: 건물 높이(m)
- A26: 지상 층수
- A9: 건축물 용도명
- A22: 자료 기준일

출처: https://ktdb.go.kr/DATA/pblcte/20250805093928585.pdf (PDF 126–127번째 인덱스 페이지, 책 인쇄 88–89쪽)

| 높이 처리 | 건물 수 | 화면에서의 의미 |
|---|---:|---|
| 정상 범위의 원본 높이 사용 | 1,752 | 제공된 높이 그대로 사용 |
| 원본 층수 × 가정 층고 | 1,242 | 높이 추정 |
| 높이·층수 부족 또는 속성 불일치 | 5,672 | 미확인 높이를 낮은 대체 모형으로 표시 |

1m보다 작은 양의 높이 7건은 건물 높이로 사용하지 않았다. 강내면에 클립된 도형에 다른 지역의 법정동명이 들어간 객체가 42건 있어, 그 42건은 외곽선만 사용하고 높이·층수·용도 속성은 미확인으로 처리했다. 이는 원본 속성의 불일치를 숨기지 않기 위한 처리이며 원본 파일은 변경하지 않는다.

층수로 높이를 추정할 때 산업 건물은 층당 4.2m, 그 외는 3.1m를 적용한다. 높이와 층수가 모두 없는 건물은 용도에 따라 낮은 대체 높이를 사용한다. 외벽·평지붕의 색은 주택, 공장·창고, 공동주택, 공공·교육, 상업, 용도 미확인으로 나눈 **시각적 표현**이다. 실제 외벽 재질, 창문의 위치, 지붕 경사나 색을 측정한 데이터는 아니다. 건물 바닥의 절대 고도는 지도 지형에서 표본을 얻어 맞추며, 고도가 아직 확인되지 않은 건물은 보류하고 다시 시도한다.

건물 속성의 기준일은 2026-11-06이다. 2023년 운행 결과와 함께 표시되지만 2023년 당시의 건물 외관을 복원한 것으로 해석하면 안 된다.

## 도로 표면

도로경계 면 안에 들어가는 중심선 표본으로 속성을 대응시킨다. 10m 이하 간격의 중심선 표본을 도로 면에 대입하며, 내부에서 확인된 길이의 80% 이상이 같은 포장 코드일 때만 그 포장 분류를 사용한다. 면과 중심선 사이의 공통 ID가 없어 공간 대응한 결과이며 정확한 원본 속성 조인은 아니다.

| 분류 | 도로 면 수 |
|---|---:|
| 포장 | 3,677 |
| 비포장 | 652 |
| 대응 불명 또는 혼합 | 845 |

`RDQ005`는 비포장, `RDQ006`은 포장이다. 포장은 반드시 아스팔트라는 뜻이 아니므로 포장 면은 중립적인 회색으로 표현한다. 폭·차로 정보는 대응 근거로 보존하되 도로 면을 확대하거나 실제 차선처럼 꾸미는 데 사용하지 않는다. 중앙선·횡단보도 좌표가 없어서 임의의 차선을 그리지 않는다.

## 표고점과 지형의 완만한 표시

표고점은 `NUME`를 이용하여 50m 격자에 가까운 8개 점의 역거리 가중 보간(IDW, 거리 제곱)을 적용한다. 가까운 표고점이 220m 이내에 없는 격자는 사용하지 않는다. 이 격자는 고도 관측값 자체가 아닌 **보간 자료**이다.

NUME의 수직 기준이 지도 엔진의 타원체 고도와 같다고 확인되지 않았으므로 두 값을 그대로 더하거나 바꾸지 않는다. 원 지형 타일의 동일 위치에서 구한 고도와 격자값의 차이의 중앙값으로 국소적인 표시 기준을 맞춘다. 이것은 공식적인 지오이드·수직 좌표 변환이 아니다. 이후 지형 타일의 세부 높낮이 차이 중 20%만 반영하며 각 격자 표본의 보정량은 ±1.2m로 제한한다.

- 원 V-World/Cesium 지형 공급원은 계속 사용한다.
- 강내면 밖, 표고점 부족 구간, 지원하지 않는 SDK 데이터는 원 지형을 사용한다.
- 타일 경계의 보정량은 0으로 이어 붙인다.
- 교량 주변과 수면 마스크 구간은 원 지형을 유지한다.
- 원 공급원의 세부 타일을 65×65 높이 표본으로 다시 표현하므로 실측 지형 정밀도를 보장하는 변환이 아니다.
- 차량·시설의 고도 조회도 같은 지형 공급원을 사용한다. 별도의 가짜 차량 경사 경로를 만들지 않는다.
- 엔진이 공개 TerrainData 보간 API를 제공하지 않으면 자동으로 원 지형을 유지한다. 화면 상태에 실제 적용 여부를 표시한다.

## 교량

92개 교량의 실제 외곽선(94개 Polygon 부분)을 사용한다. 첨부 자료에는 상판 고도가 없어 외곽선의 긴 방향 양쪽 접근부를 지형에서 표본 추출하여 상판 높이를 추정한다. 0.35m 상판 두께는 시각적 표현이다. 교각 높이, 난간 구조, 실제 교량의 외관을 임의로 측정 사실처럼 만들지 않는다.

접근부 높이 차이가 교량 길이에 비해 지나치게 크면 상판을 무리하게 기울여 만들지 않고 해당 입체 모형을 보류한다. 따라서 실제 표시되는 교량 수는 지형 고도 응답 상태에 따라 전체 92개보다 작을 수 있다. 운행 경로의 교량 고도를 관측한 데이터가 추가되면 그 기록을 우선해야 한다.

## 성능과 레이어

650m 공간 구역으로 92개의 JSON 타일을 만들었다. 카메라 시야·선택 차량 부근의 타일을 우선 로드하며, 한 번에 세 타일씩 지형 표본을 조회한다. 도로는 GroundPrimitive, 건물 외벽·지붕과 교량은 묶음 Primitive를 사용한다. 먼 GPU 객체는 제거하고 JSON 자료를 재사용해 되감기와 차량 전환을 지원한다.

지역 건물 모형이 실제로 만들어진 경우에는 V-World의 기본 건물 레이어를 숨겨 중복을 줄인다. 지역 건물 레이어를 끄거나 연결을 해제하면 기본 건물 레이어가 돌아온다. 기본 지도 영상·도로망·경계와 로드뷰를 대체하지 않는다.

## 재생성 및 검증

사용자는 ZIP을 실행하는 데 Python GIS 라이브러리가 필요 없다. 개발자가 원본 자료를 바꾸고 다시 변환할 때만 다음을 실행한다.

```sh
python -m pip install numpy scipy
python scripts/build_environment.py
node --test tests/environment.test.mjs
```

원본 파일의 SHA-256은 `data/environment/manifest.json`에 기록했다. 변환 통계는 `data/environment/validation.json`에 있다.

테스트는 전체 건물 8,666개, 도로 Polygon 5,195개, 교량 Polygon 94개의 Cesium 지오메트리 생성을 검사한다. 다른 테스트는 원본 수량, 속성 불일치 격리, Polygon 구멍, 고도 보정 한도·수면·교량·타일 경계, 지형 요청 대기·자식 타일 마스크, 지도 종료 후 늦게 도착한 비동기 응답의 정리를 검사한다. 실제 V-World 인증키와 사용자 브라우저 GPU를 이용한 현장 렌더링 확인은 별도이다.

## 코드 연결

```js
import Environment3D from './environment3d.js';
const environment = new Environment3D({ onStatus: updateEnvironmentStatus });
await environment.attach(scene.viewer, scene.C, {
  nativeBuildings: show => scene._setVWorldBuildings?.(show)
});
environment.setVisible({ buildings: true, roads: true, bridges: true, terrain: true });
environment.update(states, { selectedId: selected, mode: camera });
// 엔진을 해제하거나 페이지를 닫을 때
environment.destroy();
```

`status.terrainChanged`가 참이면 앱에서 보관하는 지형 높이 캐시를 비운다. 지형 공급원이 나중에 바뀌는 경우에도 모듈이 새 공급원을 감시하여 다시 연결하며, 자기 자신의 래퍼를 중복으로 감싸지 않는다.
