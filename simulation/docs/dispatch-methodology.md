# DRT 경로 및 의사결정 데이터

## 무엇을 재현하는가

이 모드는 팀의 **실제 시뮬레이션에서 확정한 차량 계획**을 재생한다. 실행 결과의 차량 이동을 보고 새로운 배차 이유를 만들어 내는 기능이 아니다. 원본의 `plans.jsonl`, `decisions.csv`, `local_search.json`, `optimizer_timing.csv`를 날짜·운영 방식·목적함수별로 변환했다.

7일 × 여객 전용/통합운영 × S0/S1/S2, 총 42개 실행을 포함한다. 여객 요청 531건은 6가지 조합에서 반복 평가되어 배차 결정 3,186건으로 나타나며, 원본 계획 스냅샷은 총 11,368개다. 이 숫자는 별개의 승객 수 3,186명을 뜻하지 않는다.

### 화면에서 읽는 순서

1. 선택한 시각까지 실제로 접수된 여객 호출을 확인한다.
2. 그 호출에 기록된 배정 차량, 제약을 통과해 점수 평가한 삽입 후보 수, 약속 승차 대기를 확인한다. `candidates_tested`는 제약 검사에서 탈락한 모든 시도까지 센 값은 아니다.
3. 선택한 차량의 **직전 기록 계획**과 **이번 확정 계획**의 남은 서비스 순서를 비교한다.
4. 같은 승객이 두 계획에 모두 있을 때 계획상 승차 ETA 및 대기시간의 변화량을 확인한다.
5. 물류하차지의 다음 계획 방문 ETA와, 국소탐색에서 실제 채택된 작업 변경을 확인한다.

앞쪽 12개 작업까지 도로 경로를 그린다. 더 긴 계획은 작업 목록에 남으며, 도식에 전체 일일 운행을 한꺼번에 중첩하지 않는다. 도로는 방향성 네트워크의 최단 **통행시간** 경로로 복원한다. 파일에 저장된 링크 순서를 이어 붙이지 않는다. 이동 중인 첫 구간은 경과한 도로 통행시간에 따라 잘라 표시한다.

## 여객은 동적, 물류는 사전 확정 수요·동적 경로

원본 `engine.py`의 실행기는 미래 여객 요청을 별도의 이벤트 달력에 보관한다. 계획기는 해당 시각에 접수된 요청만 본다. 신규 호출 시 승차·하차 위치를 기존 계획의 가능한 위치에 삽입하여 평가한다.

물류의 목적지와 일일 수량은 사전에 정해져 있고, 08:30에 작업 가능 상태가 된다. **배송 순서와 차량별 경로는 고정이 아니다.** 원본 `optimizer.py`는 다음 변경을 시험한다.

| 원본 연산 | 의미 |
| --- | --- |
| `RELOCATE_STOP` | 같은 차량 안에서 우체국 적재 방문 또는 물류하차 작업의 위치 변경 |
| `RELOCATE_TRIP` | 아직 실행하지 않은 적재·하차 묶음을 다른 차량으로 이동 |
| `TRANSFER_UNLOADED_UNIT` | 아직 적재하지 않은 물량 한 개를 예정된 적재 방문/차량 사이에서 이전 |

이미 수행한 작업과 이미 적재한 물량의 소유 차량은 유지한다. 호출이 이동 중에 들어오면 다음 실제 도로 노드까지 진행하는 구간을 고정한 후 남은 계획을 바꾼다. 이는 순간적인 유턴이나 좌표 순간이동을 허용한다는 뜻이 아니다. 교차로별 회전 금지 데이터는 원본 모델에 제공되어 있지 않다.

이 방법은 **온라인 승하차 삽입과 다회차 용량제약 VRP 국소탐색을 결합한 휴리스틱**이다. 원본 검색 설정은 국소탐색 최대 2회, 연산별 후보 예산 60개다. 전역 최적해를 수학적으로 보장하지 않는다.

## 목적함수와 제약

| 시나리오 | 첫 번째 비교값 | 동점 시 비교값 |
| --- | --- | --- |
| S0 | 남은 전체 차량 계획 거리 + 최종 복귀 거리, km | 아직 계획에 남은 승객의 인원 가중 대기 합, 인·분 |
| S1 | 아직 계획에 남은 승객의 인원 가중 대기 합, 인·분 | 남은 전체 차량 계획 거리 + 최종 복귀 거리, km |
| S2 | 거리와 인원 가중 대기의 비용계수 조합 | 거리, km |

운행 중 이미 고정된 활성 구간은 후보 간 동일하므로 원본 후보 점수 계산에서 제외된다. 표시되는 목적함수 점수는 이 **남은 계획의 점수**이며, 하루 누적 주행거리나 최종 관측 평균 대기시간과 다른 값이다. S2 계수는 참고용 가정으로 취급한다. 별도 운영원가 산정값으로 이 계수를 대체하지 않았다.

실제 코드에서 지키는 핵심 조건은 승객 11명, 물류 8개, 승차→하차 선후관계, 기존 승차 약속의 변경 허용 1분, 직접 이동시간 대비 최대 승차시간 조건, 탑승객이 없는 우체국 적재, 배송 마감과 복귀 마감이다. **15분 대기는 강제 상한이 아니다.** 화면에 15분보다 큰 대기가 나타나도 원본 결과 그대로다.

## 기록값과 계산값 구분

| 항목 | 근거 |
| --- | --- |
| 호출 시각·배정 차량·수락 여부 | 원본 `decisions.csv` |
| 검토 후보 수·승차 약속 시각·최종 점수 | 원본 `decisions.csv` |
| 차량별 작업 순서·활성 구간·탑승/적재 상태 | 원본 `plans.jsonl` |
| 국소탐색 전후 점수·검토 수·채택된 연산 횟수 | 원본 `local_search.json` |
| 계산 실행 시간 | 원본 `optimizer_timing.csv` |
| 계획의 나머지 승차·하차·물류 ETA | 원본 방향성 링크 통행시간 + 계획의 서비스 시간으로 재계산 |
| 도로 위 중간 위치와 계획 선형 | 같은 방향성 도로망으로 복원·보간, GPS 측정값 아님 |
| 두 계획의 예상 대기/하차 ETA 차이 | 검증된 계획 ETA의 차이; 아래 제한 참조 |

**미선택 후보별 상세 점수와 거절 이유는 원본에 없다.** 화면은 존재하는 검토 후보 수와 채택 결과를 보여 주며, 다른 차량의 대기시간이나 “물류를 먼저 하면 몇 분 늦음” 같은 수치를 만들어 내지 않는다.

“직전 기록 계획”은 이전 `plans.jsonl` 스냅샷의 아직 끝나지 않은 작업이다. 동일 최적화 호출 안에서 저장된 미선택 후보가 아니다. 서로 다른 기록 시점의 계획을 비교하기 때문에, 차이는 그 사이의 호출·서비스 완료·물류 재배치 전체를 반영한다. **차이를 물류 때문에 생긴 인과적 지연이라고 해석해서는 안 된다.** 특정 작업을 제거한 대안 효과를 분석하려면 원본 상태를 복구한 별도 알고리즘 재실행과 검증이 필요하다.

물류 영향값은 같은 하차지의 **다음 예정 방문**을 비교한다. 동일 하차지에 여러 차례 분할 배송하는 경우 전체 물량의 마지막 도착시간이나 특정 택배 하나의 지연을 뜻하지 않는다.

## 재계산 검증

- 42개 실행의 승객 ID, 호출 시각, 배정 차량을 기존 웹 재생 데이터와 대조했다.
- 신규 수락 3,186건의 계획 ETA를 원본 승차 약속과 비교했다. 최대 오차는 **0분**이다.
- 점수가 기록된 7,665개 스냅샷에서 전체 남은 차량 계획의 거리/인원 가중 대기를 다시 합산했다. 최대 차이는 부동소수점 반올림 수준인 약 `9.1e-13`이다. S2는 미확정 계수를 추정하지 않고 거리 보조 점수를 검증했다.
- 모든 계획 작업은 해당 시각까지 공개된 여객 요청만 참조하는지 확인했다.
- 24,344개 계획 경로의 링크 연결관계, 일방통행 방향, 통행시간 합을 검사했다.
- 시간 되감기, 차량 변경, 아직 접수되지 않은 호출 차단, 승차 전 실제 대기 결과 차단을 검증했다. 미래 기록을 의도적으로 바꾸어도 현재 의사결정 화면은 달라지지 않는다.

보고서는 `docs/dispatch-validation.json`, `docs/dispatch-core-test-results.json`에 있다. 검증은 새로운 운행 결과를 만들거나 원본 `data/runs`를 변경하지 않는다.

## 재생성

현재 ZIP에는 변환 완료된 42개 JSON이 들어 있다. 일반 사용자는 이 명령을 실행할 필요가 없다.

개발자가 원본을 다시 변환하려면 [MetroRookies의 최종확정 실행결과 폴더](https://github.com/km-minsang/MetroRookies/tree/main/06_%EB%B6%84%EC%84%9D%EA%B2%B0%EA%B3%BC/%EA%B9%80%EB%AF%BC%EC%83%81_%EC%A3%BC%EC%B0%A83%EB%B6%84_%EC%B5%9C%EC%A2%85%ED%99%95%EC%A0%95)에서 7개 날짜 ZIP을 같은 위치에 풀고, 이 프로젝트 폴더에서 실행한다.

```bash
python scripts/decision_convert.py --results /path/to/gangnae_online/results
node tests/dispatch-core.test.mjs
```

변환기는 Python 표준 라이브러리만 사용한다. `network.json`과 `split_links_4326.geojson`의 노드·링크 정합성을 먼저 검사하며, 경로가 연결되지 않거나 원본 승차 약속과 재계산 ETA가 다르면 변환을 중단한다. 누락 경로를 직선으로 대신하지 않는다.
